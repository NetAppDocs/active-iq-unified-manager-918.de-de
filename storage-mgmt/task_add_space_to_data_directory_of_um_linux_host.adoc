= Hinzufügen von Speicherplatz zum Datenverzeichnis des Linux Hosts in Active IQ Unified Manager
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Falls Sie bei der ursprünglichen Einrichtung des Linux-Hosts dem  `/opt/netapp/data` Verzeichnis nicht genügend Speicherplatz zur Unterstützung von Unified Manager zugewiesen und anschließend Unified Manager installiert haben, können Sie nach der Installation zusätzlichen Speicherplatz hinzufügen, indem Sie den Speicherplatz im  `/opt/netapp/data` Verzeichnis erhöhen.

.Bevor Sie beginnen
Sie benötigen Zugriff als Root-Benutzer auf den Red Hat Enterprise Linux Rechner, auf dem Unified Manager installiert ist.

Wir empfehlen Ihnen, die Unified Manager Datenbank zu sichern, bevor Sie die Größe des Datenverzeichnisses erhöhen.

.Schritte
. Die Anmeldung als Root-Benutzer erfolgt auf dem Linux-Rechner, auf dem zusätzlicher Festplattenspeicher hinzugefügt werden soll.
. Das Beenden des Unified Manager Service und der zugehörigen MySQL Software erfolgt in der angegebenen Reihenfolge: `systemctl stop ocieau ocie mysqld`
. Es wird ein temporärer Sicherungsordner (zum Beispiel `/backup-data`) mit ausreichendem Speicherplatz für die Daten im aktuellen `/opt/netapp/data` Verzeichnis benötigt.
. Der Inhalt und die Berechtigungskonfiguration des vorhandenen `/opt/netapp/data`Verzeichnisses sind in das Sicherungsdatenverzeichnis zu kopieren:
+
`cp -arp /opt/netapp/data/* /backup-data`

. Wenn SE Linux aktiviert ist:
+
.. SE Linux-Typ für Ordner in einem vorhandenen `/opt/netapp/data` Ordner:
+
`se_type=`ls -Z /opt/netapp/data| awk '{print $4}'| awk -F: '{print $3}'| head -1`

+
Das System gibt eine Bestätigung zurück, die in etwa wie folgt aussieht:

+
[listing]
----
echo $se_type
mysqld_db_t
----
.. Der `chcon` Befehl legt den SE Linux Typ für das Backup-Verzeichnis fest:
+
`chcon -R --type=mysqld_db_t /backup-data`



. Entfernen des Inhalts des  `/opt/netapp/data` Verzeichnisses:
+
.. `cd /opt/netapp/data`
.. `rm -rf *`


. Die Größe des  `/opt/netapp/data` Verzeichnisses ist mithilfe von LVM-Befehlen oder durch Hinzufügen zusätzlicher Festplatten auf mindestens 150 GB zu erweitern.
+
[NOTE]
====
Wenn Sie `/opt/netapp/data` von einer Festplatte erstellt haben, sollten Sie nicht versuchen, `/opt/netapp/data` sie als NFS- oder CIFS-Freigabe einzubinden. Denn in diesem Fall funktionieren einige LVM-Befehle, wie beispielsweise `resize` und `extend`, möglicherweise nicht wie erwartet, wenn Sie versuchen, den Speicherplatz zu erweitern.

====
. Stellen Sie sicher, dass Eigentümer (mysql) und Gruppe (root) des  `/opt/netapp/data`Verzeichnisses unverändert sind:
+
`ls -ltr /opt/netapp/ | grep data`

+
Das System gibt eine Bestätigung zurück, die in etwa wie folgt aussieht:

+
[listing]
----
drwxr-xr-x.  17 mysql root  4096 Aug 28 13:08 data
----
. Bei aktiviertem SE Linux muss der Kontext für das  `/opt/netapp/data`Verzeichnis weiterhin auf mysqld_db_t gesetzt sein:
+
.. `touch /opt/netapp/data/abc`
.. `ls -Z /opt/netapp/data/abc`
+
Das System gibt eine Bestätigung zurück, die in etwa wie folgt aussieht:

+
[listing]
----
-rw-r--r--. root root unconfined_u:object_r:mysqld_db_t:s0 /opt/netapp/data/abc
----


. Es empfiehlt sich, die Datei `abc` zu löschen, damit diese überflüssige Datei in Zukunft keinen Datenbankfehler verursacht.
. Den Inhalt aus `backup-data` back in das entpackte `/opt/netapp/data` Verzeichnis kopieren:
+
`cp -arp /backup-data/* /opt/netapp/data/`

. Wenn SE Linux aktiviert ist, ist der folgende Befehl auszuführen:
+
`chcon -R --type=mysqld_db_t /opt/netapp/data`

. Start des MySQL-Dienstes:
+
`systemctl start mysqld`

. Nach dem Start des MySQL-Service erfolgt der Start der Services ocie und ocieau in der angegebenen Reihenfolge:
+
`systemctl start ocie ocieau`

. Nachdem alle Services gestartet sind, kann der Sicherungsordner `/backup-data` gelöscht werden:
+
`rm -rf /backup-data`
