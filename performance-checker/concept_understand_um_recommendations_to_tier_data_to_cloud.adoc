= Die Empfehlungen von Active IQ Unified Manager für das Tiering von Daten in die Cloud können in Active IQ Unified Manager überprüft werden.
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Die Ansicht „Performance: Alle Volumes“ zeigt Informationen zur Größe der auf dem Volume gespeicherten inaktiven (kalten) Benutzerdaten an. In manchen Fällen identifiziert Unified Manager bestimmte Volumes, die von einer Tiering der inaktiven Daten auf die Cloud-Ebene (Cloud-Anbieter oder StorageGRID) eines für FabricPool aktivierten Aggregats profitieren würden.

[NOTE]
====
FabricPool wurde in ONTAP 9.2 eingeführt. Wenn Sie also eine Version der ONTAP Software vor 9.2 verwenden, erfordert die Empfehlung von Unified Manager zum Tiering von Daten ein Upgrade Ihrer ONTAP Software. Außerdem wurde die  `*auto*` Tiering-Richtlinie in ONTAP 9.4 eingeführt, und die  `*all*` Tiering-Richtlinie wurde in ONTAP 9.6 eingeführt. Wenn die Empfehlung also die Verwendung der auto Tiering-Richtlinie vorsieht, müssen Sie ein Upgrade auf ONTAP 9.4 oder höher durchführen.

====
Die folgenden drei Felder in der Ansicht „Performance: Alle Volumes“ geben Auskunft darüber, ob Sie die Festplattenauslastung Ihres Storage-Systems verbessern und Speicherplatz auf dem Performance-Tier einsparen können, indem Sie inaktive Daten in die Cloud-Ebene verschieben.

* *Tiering-Richtlinie*
+
Die Tiering-Richtlinie legt fest, ob die Daten auf dem Volume auf der Performance-Ebene verbleiben oder ob ein Teil der Daten von der Performance-Ebene in die Cloud-Ebene verschoben wird.

+
Der Wert in diesem Feld gibt die für das Volume festgelegte Tiering-Richtlinie an, auch wenn sich das Volume aktuell nicht auf einem FabricPool Aggregat befindet. Die Tiering-Richtlinie wird erst wirksam, wenn sich das Volume auf einem FabricPool Aggregat befindet.

* *Kalte Daten*
+
Die Anzeige der kalten Daten gibt die Größe der auf dem inaktiven (kalten) Volume gespeicherten Benutzerdaten an.

+
Ein Wert wird hier nur bei Verwendung von ONTAP 9.4 oder höher angezeigt, da dies voraussetzt, dass das Aggregat, auf dem das Volume bereitgestellt ist, die  `*inactive data reporting parameter*` auf  `*enabled*` gesetzt hat und dass die Mindestanzahl an Kühltagen erreicht wurde (für Volumes, die die Tiering-Richtlinie  `*snapshot-only*` oder  `*auto*` verwenden). Andernfalls wird der Wert als "`N/A`" aufgeführt.

* *Cloud-Empfehlung*
+
Nachdem genügend Informationen über die Datenaktivität auf dem Volume erfasst wurden, kann Unified Manager feststellen, dass keine Maßnahmen erforderlich sind oder dass Sie Speicherplatz auf dem Performance Tier sparen können, indem Sie inaktive Daten auf das Cloud Tier verschieben.



[NOTE]
====
Das Feld „Kalte Daten“ wird alle 15 Minuten aktualisiert, das Feld „Cloud-Empfehlung“ hingegen alle 7 Tage, wenn die Analyse kalter Daten auf dem Volume durchgeführt wird. Daher kann die genaue Menge kalter Daten zwischen den Feldern abweichen. Das Feld „Cloud-Empfehlung“ zeigt das Datum an, an dem die Analyse ausgeführt wurde.

====
Wenn die Berichterstellung über inaktive Daten aktiviert ist, zeigt das Feld „Kalte Daten“ die genaue Menge an inaktiven Daten an. Ohne die Funktion zur Berichterstellung über inaktive Daten verwendet Unified Manager Performance-Statistiken, um festzustellen, ob Daten auf einem Volume inaktiv sind. Die Menge an inaktiven Daten wird in diesem Fall nicht im Feld „Kalte Daten“ angezeigt, sondern erst, wenn Sie den Mauszeiger über das Wort „Tier“ bewegen, um die Cloud-Empfehlung anzuzeigen.

Die angezeigten Cloud-Empfehlungen lauten:

* *Lernprozess*. Es wurden noch nicht genügend Daten gesammelt, um eine Empfehlung auszusprechen.
* *Tier*. Die Analyse hat ergeben, dass das Volume inaktive (kalte) Daten enthält und Sie das Volume so konfigurieren sollten, dass diese Daten in das Cloud-Tier verschoben werden. In einigen Fällen kann dies erfordern, dass Sie das Volume zuerst in ein FabricPool fähiges Aggregat verschieben. In anderen Fällen, in denen sich das Volume bereits auf einem FabricPool Aggregat befindet, müssen Sie lediglich die Tiering-Richtlinie ändern.
* *Keine Aktion*. Entweder enthält das Volume nur sehr wenige inaktive Daten, das Volume ist auf einem FabricPool Aggregat bereits auf die Tiering-Richtlinie "`auto`" gesetzt, oder es handelt sich bei dem Volume um ein Datensicherungs-Volume. Dieser Wert wird auch angezeigt, wenn das Volume offline ist oder in einer MetroCluster Konfiguration verwendet wird.


Zum Verschieben eines Volume oder zum Ändern der Volume-Tiering-Richtlinie oder der Einstellungen für die Berichterstattung über inaktive Aggregatdaten können ONTAP System Manager, die ONTAP CLI-Befehle oder eine Kombination dieser Tools verwendet werden.

Wenn Sie in Unified Manager mit der Rolle *Application Administrator* oder *Storage Administrator* angemeldet sind, ist der Link *Configure Volume* in der Cloud-Empfehlung verfügbar, wenn Sie den Mauszeiger über das Wort *Tier* bewegen. Mit dieser Schaltfläche lässt sich die Seite *Volumes* in System Manager öffnen, um die empfohlene Änderung vorzunehmen.
