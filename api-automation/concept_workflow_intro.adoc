= Informationen zu gängigen API-Workflows für die Speicherverwaltung in Active IQ Unified Manager
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Die gängigen Workflows bieten Entwicklern von Client-Applikationen Beispiele dafür, wie Active IQ Unified Manager APIs von einer Client-Applikation aufgerufen werden können, um gängige Storage-Managementfunktionen auszuführen. Dieser Abschnitt enthält einige dieser Beispiel-Workflows.

Die Workflows beschreiben einige der häufig verwendeten Anwendungsfälle für das Storage-Management sowie Beispielcode zur Verwendung. Jede Aufgabe wird anhand eines Workflow-Prozesses beschrieben, der aus einem oder mehreren API-Aufrufen besteht.



[[understand-the-api-calls-used-in-the-workflows]]
== Die in den Workflows verwendeten API-Aufrufe verstehen

Sie können von Ihrer Unified Manager Instanz aus die Seite der Online-Dokumentation anzeigen, die die Details zu jedem REST API-Aufruf enthält. Dieses Dokument wiederholt die Details der Online-Dokumentation nicht. Jeder API-Aufruf, der in den Workflow-Beispielen in diesem Dokument verwendet wird, enthält nur die Informationen, die Sie benötigen, um den Aufruf auf der Dokumentationsseite zu finden. Nachdem Sie einen bestimmten API-Aufruf gefunden haben, können Sie die vollständigen Details des Aufrufs prüfen, einschließlich der Eingabeparameter, Ausgabeformate, HTTP-Statuscodes und des Typs der Anfrageverarbeitung.

Die folgenden Informationen sind für jeden API-Aufruf innerhalb eines Workflows enthalten, um den Aufruf auf der Dokumentationsseite zu finden:

* Kategorie: Die API-Aufrufe sind auf der Dokumentationsseite in funktional verwandte Bereiche oder Kategorien unterteilt. Ein bestimmter API-Aufruf kann durch Scrollen zum Seitenende und Klicken auf die entsprechende API-Kategorie gefunden werden.
* HTTP-Verb (Aufruf): Das HTTP-Verb identifiziert die Aktion, die an einer Ressource ausgeführt wird. Jeder API-Aufruf wird über ein einzelnes HTTP-Verb ausgeführt.
* Pfad: Der Pfad bestimmt die spezifische Ressource, auf die sich die Aktion im Rahmen eines Aufrufs bezieht. Die Pfadzeichenfolge wird an die Core-URL angehängt, um die vollständige URL zu bilden, die die Ressource identifiziert.
